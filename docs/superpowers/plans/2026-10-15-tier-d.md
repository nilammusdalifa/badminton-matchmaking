# Tier D

**Goal:** A fourth tier, D below C, so teams can be balanced more finely. Existing A/B/C players keep their tier; the organizer moves their weakest Cs down to D.

## The rule

**Tier points: A=3, B=2, C=1, D=0** (`LEVEL_RANK`, read through `tierPointsOf`). Only gaps between teams are ever used, so with no D players everything behaves exactly as before. All 222 existing tests passed unchanged after adding D.

**`tierPointsOf`:** an unknown level, such as data from a different app version, counts as B. `oppEdge`, the ranking score, team splits, `bestSplitGap` and requested-pair opponents all read it, so the duplicate `tierPoints` in the stats code is gone.

**Lower tier = C or D** (`isLower` in `hardGames.ts`). It's explicit, so a deleted player is neither upper nor lower:
- An A/B player's carry counts with a C or D partner.
- A must-play C or D blocks a hard game.
- Next to a hard game, an A with a C or D is avoided.
- Hard games stay all-A/B.

**`TIER_STEP`** (0.1 per tier point in the ranking score) is unchanged. D extends the scale downward, so a tier point means what it did.

## Measured (`matchmaking.sim.test.ts`, "fourth tier (D)")

Same nights and hidden skills, tiers set in 3 or 4 equal groups from a view misjudged by 0.4 sd. "Lopsided" means the favourite by true skill has more than a 70% chance:

| Night | 3 tiers | 4 tiers |
|---|---|---|
| 15 players, 2 courts | 27.1% | 20.6% |
| 16 players, 2 courts | 25.9% | 21.4% |
| 8 players, 2 courts | 27.1% | 21.5% |
| 8 players, 1 court | 32.8% | 21.0% |
| 6 players, 1 court | 23.4% | 22.9% |

- **Rotation was the same:** games gap, back-to-back, skips and new groups were identical, and the 90th-percentile wait was the same or shorter.
- **Partner variety** fell slightly except at 6 players (e.g. 16 players: 3.70 → 3.54 different partners). This is the same trade-off as the even-split tie-break.
- **Hard games on 3A/4B/4C/4D** stay within the 3A/5B/7C limits:
  - 2.24 hard games per A/B player.
  - At most 2 carries.
  - Lower tiers wait at most one match longer.
  - An A with a C or D next to a hard game 7% of the time.

## Rankings (`rankings.sim.test.ts`)

**Draw luck halves with 4 tiers:** 0.169 → 0.084 (16 players), 0.142 → 0.049, 0.090 → 0.039.

**How closely the whole order follows true skill drops,** e.g. 0.380 → 0.290. It drops as much under the old win-rate rule (0.382 → 0.313). Closer matches say less about who is strongest, so the order leans more on who played above their tier.

## UI

- **The tier picker** has A–D as 44px buttons. In the add-player form the buttons drop under the label at 320px.
- **Copy** names C or D in the Hard games description, and the info sheet lists D=0.
- **Rankings rows** keep "W–L", "% won" and "% pts" whole when the line wraps.

## Rollout

- **No migration.** Firebase rules don't validate `level`.
- **Every device needs one reload** (there's no service worker). An old build would count a D player as C in rankings and get NaN costs when pairing.
